# 유소년 축구 선수 데이터 플랫폼 (Pilot)

> 에이전트가 경기를 보며 **클릭으로 기록**하고, 누적 데이터가 **하나의 가치 점수(레이더)** 로 확인되는 서비스.

이 저장소는 기획서(v0.1)를 **본질 → UI → 기술 → 동작하는 MVP**까지 한 번에 정리한 파일럿입니다.
오버엔지니어링 없이, 지금 당장 폰에서 열어 검증할 수 있는 형태를 목표로 했습니다.

## ▶️ 바로 실행

```bash
cd youth-soccer-platform/app
python3 -m http.server 8099
# 폰/브라우저에서 http://localhost:8099 접속
```

첫 실행 시 데모 선수(이승원)와 3경기 기록이 자동 시드됩니다.
빌드 도구·서버·회원가입 없이 바로 동작합니다. (데이터는 브라우저 localStorage에 저장)

## 🎯 한 줄 본질

기획서에는 기능이 16개 챕터로 나열돼 있지만, **핵심 루프는 하나**입니다.

> **경기를 보며 탭한다 → 데이터가 쌓인다 → 가치 점수(레이더)로 본다.**

나머지(AI 분석, 외부 연동, 랭킹, 구단 서비스)는 이 루프가 검증된 **후에** 붙는 확장입니다.
그래서 MVP는 이 루프 하나만 완성도 높게 만듭니다. 자세한 논리는 [`docs/01-본질과-문제정의.md`](docs/01-본질과-문제정의.md).

## 🧮 가치 점수 모델 (기획서의 계산식 그대로)

로데이터 → **표준화(Z)** → **가중합** → **점수화(T=50+10Z)** 로 5개 KPI를 계산합니다.
기획서 예시(이승원 기회창출 44.7점)를 재현하도록 리그 기준값을 역산해 넣었습니다.
전체 정의는 [`docs/05-KPI-가치점수-모델.md`](docs/05-KPI-가치점수-모델.md), 구현은 [`app/js/kpi.js`](app/js/kpi.js).

## 🗄️ 저장 전략 (소규모)

- **Pilot**: 백엔드 0개. 브라우저 localStorage로 핵심 루프만 검증.
- **다음 단계**: Supabase(Postgres + Auth) 무료 티어. `store.js`의 구조가 그대로 테이블이 되도록 설계 → 마이그레이션 비용 최소화.
- 상세 스키마·다이어그램은 [`docs/04-기술아키텍처.md`](docs/04-기술아키텍처.md).
